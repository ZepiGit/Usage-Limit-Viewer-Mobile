# Building and releasing

## Build Android

Use JDK 21 for development and all CI jobs, Android SDK platform 37.0 and Build Tools 36.0.0 or later. Set `ANDROID_HOME` or `sdk.dir` in untracked `local.properties`. Install the platform and, for a phone emulator, the system image with:

```sh
sdkmanager 'platforms;android-37.0' 'system-images;android-37.0;default;x86_64'
```

Use command-line tools build `15859902` (22.0) for AVD creation. Older tools can misparse the dotted `37.0` image version and generate an `android-0` target. CI pins that tools build without changing the SDK setup action's major, records the selected tools and AVD metadata, and requires `target=android-37.0` before launch.

The app has minSdk 26 and compiles and targets API 37. The wrapper pins Gradle 9.7.0 and its distribution checksum; the toolchain uses AGP 9.3.1, Kotlin 2.4.21, KSP 2.3.14 and Compose compiler 2.4.21. AGP's built-in Kotlin and new DSL stay enabled, without the `org.jetbrains.kotlin.android` plugin. AGP and Gradle require at least JDK 17, but the project uses JDK 21, including for Robolectric 4.18's API 37 support. Explicit older regression SDKs remain in tests. Java 17 bytecode is preserved.

The versions are coordinated against the [AGP 9.3 compatibility table](https://developer.android.com/build/releases/agp-9-3-0-release-notes), [Kotlin's Gradle/AGP compatibility table](https://kotlinlang.org/docs/gradle-configure-project.html) and [KSP requirements](https://kotlinlang.org/docs/ksp-overview.html). The merged CI action upgrade uses `gradle/actions@v6` only with `cache-provider: basic`; do not enable its default enhanced cache.

From the repository root:

```sh
./gradlew :app:assembleDebug :app:assembleRelease
```

On Windows, use `gradlew.bat`. The debug APK is `app/build/outputs/apk/debug/app-debug.apk`; its application ID is `com.usagelimits.debug`, so it installs separately from release builds. Release output is `app/build/outputs/apk/release/app-release.apk`.

CI runs `:app:testDebugUnitTest :app:lintDebug`. Lint aborts on errors and writes HTML and XML reports under `app/build/reports/`. Existing warnings remain warnings, with no baseline hiding them.

The debug-build Credits smoke checks English and German selections, block order, localized balances and saved choices after force-stop. A Compact preview can move its layout selector above the Settings viewport. Hiding credits can likewise move its switch above the viewport; enabling Show credits can move it below. The smoke scrolls back to observe the requested state without repeating the tap. A visible control with the wrong state still fails. The Python harness tests cover these hierarchy and input checks, not the installed emulator journey.

Configure `Merge gate` (`.github/workflows/gate.yml`) as the required status check when enabling branch protection on `main`. Require a pull request and an up-to-date branch. The gate runs on every pull request and judges the `pull_request` and `push` runs on its head commit, except its own and release builds (`release.yml`). Manual, scheduled and Dependabot update runs are listed as not judged and neither block nor delay it. A cancelled run counts as passing only if another judged run of the same workflow succeeded on that commit. A tag that points at the head commit starts CI as well, because GitHub ignores path filters for tag pushes ([#98](https://github.com/ZepiGit/Usage-Limit-Viewer-Mobile/issues/98)). Those runs are `push` runs and are judged like any other: a failed one blocks the pull request, and a passed one can stand in for a cancelled run of the same workflow. When a tag run blocks, re-run that run until it passes, then re-run the gate, or move the pull request's head on by a commit.

The gate decides from the runs visible when polling ends; a run or re-run that appears later does not invalidate an earlier pass. After a failed CI job passes on re-run, or when CI finishes after the gate gave up at its 120-minute deadline, open the pull request's Merge gate run and choose **Re-run all jobs**. If GitHub no longer offers a re-run, push a new commit. The gate runs the script from the pull request itself, so a pull request that changes `.github/workflows/` or `tools/merge_gate.py` has to be read: a green gate proves nothing about it. To judge a commit by hand, run the script from a workstation: `GITHUB_REPOSITORY=ZepiGit/Usage-Limit-Viewer-Mobile GITHUB_TOKEN=$(gh auth token) python3 tools/merge_gate.py <full sha>`.

## Dependency updates

The Android toolchain moves together, outside Dependabot: AGP, Gradle, Kotlin, KSP and the Compose compiler must remain compatible. The coordinated API 37 upgrade removes the first-wave AndroidX, Coroutines, Serialization and OkHttp version bounds now that their current stable versions pass the consumer tests. Library and security updates may advance normally; the coupled toolchain remains excluded. Room, WorkManager, Lifecycle, Glance and Compose updates stay grouped separately so unrelated libraries do not block each other.

After upgrading CI actions, run the full Android and iOS workflows on a maintainer branch. Dependabot runs skip the signed API 37 release-upgrade smoke. The Android workflow uses `gradle/actions` v6 with `cache-provider: basic` to retain MIT-licensed caching without the separate Enhanced Caching terms. Basic caching does not provide Enhanced Caching's cleanup or deduplication. The release workflow remains uncached, and artifact uploads retain zipped, explicitly named artifacts for the existing download steps.

## Signing

Supply all four values for a distribution build:

| Environment variable | Alternative Gradle property or environment variable |
| --- | --- |
| `ANDROID_KEYSTORE_PATH` | `USAGE_LIMITS_STORE_FILE` |
| `ANDROID_KEYSTORE_PASSWORD` | `USAGE_LIMITS_STORE_PASSWORD` |
| `ANDROID_KEY_ALIAS` | `USAGE_LIMITS_KEY_ALIAS` |
| `ANDROID_KEY_PASSWORD` | `USAGE_LIMITS_KEY_PASSWORD` |

A nonblank `ANDROID_*` environment value takes precedence, followed by the `USAGE_LIMITS_*` Gradle property, then its environment value. Keep local properties in your user `.gradle/gradle.properties` and use an absolute keystore path.

With every signing value absent, release builds use the debug key for local installation. Partial settings fail instead of falling back. Distribution requires the existing release key. Keep that key, passwords and provisioning credentials outside the repository and under owner control. Disable Gradle's configuration cache for signed builds.

```sh
./gradlew --no-configuration-cache :app:bundleRelease :app:assembleRelease
```

The bundle is `app/build/outputs/bundle/release/app-release.aab`. Retain the matching R8 `mapping.txt` with the minified APK and AAB. Set `ANDROID_VERSION_NAME` and `ANDROID_VERSION_CODE` for distribution; local defaults are the source version name and reachable commit count.

## Preserving data on upgrade

An in-place Android update requires the same application ID, the same signing key and a version code that is not lower. Publish with a strictly larger code. Compare the candidate with the previous distributed APK using `aapt dump badging` and `apksigner verify --verbose --print-certs`; confirm `com.usagelimits` and the release signer's SHA-256 digest.

Use `adb install -r` to update a compatible installation. If Android rejects it, obtain the correctly signed build instead of uninstalling. Uninstalling deletes accounts, encrypted credentials, cached readings and widget configuration. Debug and release application IDs have separate storage, and debug and release signers cannot replace each other.

The committed `app/debug.keystore` gives local and CI builds a consistent debug identity. Production keeps its existing release signer. Room uses additive migrations from shipped schemas rather than destructive fallback. Full history is required when deriving version codes from commit count; shallow checkouts and divergent branches need an explicit code above the previous release.

## Release artifacts

The release workflow accepts a stable `major.minor.patch` version through a `v*` tag or manual dispatch. It pins jobs to one commit and builds artifacts without publishing a GitHub release or submitting to stores.

Android signing uses repository secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` and `ANDROID_KEY_PASSWORD`. The decoded key is temporary and removed during cleanup. The iOS job generates the project from `ios/UsageLimits/project.yml` and produces an unsigned archive. The owner supplies distribution signing and provisioning separately.

Download `release-assets-<version>` from the matching run. It contains versioned APK, AAB, R8 mapping and iOS archive files, `RELEASE-METADATA.txt` and `SHA256SUMS`. Check the metadata's commit, version name and build number against the selected tag, then run `sha256sum --check SHA256SUMS` in that directory. Preserve those same files through publication. A subsequent release uses a new version rather than replacing published tags or assets.

On an Android 17 device, perform A9–A13 in this order:

- [ ] **A9, touch resize:** long-press a placed widget, confirm the resize frame opens, then drag its handles by touch. After release, confirm the new size holds and the widget keeps its content and configuration. CI checks only keyboard move and resize, not this touch path.
- [ ] **A10, widget capacity:** add enough accounts to fill Account Rings. On a small or low-resolution display, place it in several sizes and in both orientations. Android 17 caps widget bitmap memory at about 6 × screen width × screen height bytes. A widget over the cap should show Glance's text-only error layout; a blank, stale or partly drawn widget is a failure. You do not need to cause an out-of-memory condition or turn off the cap.
- [ ] **A11, keyboard masking:** on the Add credit balance screen, type an API key with a hardware keyboard. Confirm every character stays masked as you type.
- [ ] **A12, provider transport:** sign in to and refresh each provider. Each connection must succeed with Certificate Transparency on, and with Encrypted Client Hello where the device and server negotiate it. Do not turn off TLS checks, and use only accounts whose holders have agreed.
- [ ] **A13, memory recovery:** put the device under memory pressure, for example by opening several large apps, then return to the app and its widgets. Confirm both recover normally and keep their configuration.

- [ ] **I2, real Lock Screen pins:** on an iPhone, add the Pinned accounts widget in all three Lock Screen forms with three accounts pinned, in English and German. **Release gate:** the inline form shows the provider glyph on a real Lock Screen, also after a timeline reload; if it does not, the release waits for the owner's choice between a bundled template image and a self-identifying text. **Release gate, inline words:** on a real Lock Screen, in English and in German, at the default text size and at the largest accessibility size (AX5), and in the narrowest inline slot the supported devices offer, the inline row shows the complete figure with its side and the stale suffix ("58% used · Stale" / "58 % verbraucht · Veraltet"), and one state without a number shows its whole word (for example "Exhausted" / "Aufgebraucht"). If the system truncates any of them, the release waits for the owner's choice in the same way as for the glyph. Then check the rest, which CI renders only as views: the glyphs and the crossed circle are tinted by the system against a real wallpaper; the circular form shows its system background; the cells keep every mark whole at the largest text size (Settings → Accessibility → Larger Text); on a device restarted after the app has written widget data (open the app and refresh first, so the widget has shown figures), before the first unlock, the widget shows "Locked" (the circular form a lock symbol) and fills in after unlocking once WidgetKit reloads it. With VoiceOver on, each cell reads its account's title, the full figure with its side or the state, and "Stale" where outdated.

On Android phones, use at least one on Android 16 or later and, where available, one with a manufacturer's own version of Android (Samsung, Xiaomi or similar), with sound and vibration on and the app's alerts set so they do not fire. CI covers this only on emulators ([Status icons](status-icons.md#what-has-been-checked-and-where)):

- [ ] **S1, visibility:** turn on Status bar icons and pin three accounts. The three icons show next to the clock with "Hide silent notifications in status bar" left as the phone ships it.
- [ ] **S2, quiet records:** first post, re-post and update: at the moment the icons first appear, after one is swiped away and returns with a refresh, and when a refresh changes a figure, the phone makes no sound, does not vibrate or blink, and no notification drops in from the top.
- [ ] **S3, ambient display:** screen off, with the phone's ambient or "wake screen for notifications" display on. First a re-post: swipe one row away while unlocked, turn the screen off and wait for a background refresh; when the row returns, the screen shows no notification pulse and does not wake. Then an update: let a background refresh change a figure; again no pulse and no wake. Repeat with always-on display enabled, where present: the always-on display may stay on, but shows no pulse for the change.
- [ ] **S4, lock-screen policy:** lock the phone with a PIN, with lock-screen notifications allowed. The status notifications appear there in the phone's own form (rows, cards or icons only).
